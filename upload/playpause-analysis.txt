### Summary of the Bug
The issue is a **State Desynchronization on Initialization**.
1.  **Wrong Default State:** When opening the playlist (Frame 4), the UI initializes with `isPlaying = true` (showing "Pause") even though the audio engine is idle.
2.  **The "Double Tap" Requirement:** The first tap (Frame 5) acts as a "corrective toggle"—it tells the system "Pause," which aligns the internal state to `false` (Idle). The UI then updates to show "Play" (Frame 6). The user must tap a second time (Frame 7) to actually trigger the `play()` command.
